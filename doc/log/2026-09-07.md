# 2026-09-07

## Project start, naming, license, scope

Tags: #naming #license #scope #toolchain #process

- Name: `pnsrouter` (GitHub Tubbles/pnsrouter, crate pnsrouter). The user chose it among pnsrouter, pns-router and pnsr. `shove` and `pns` are taken on crates.io; pns-router is the name of rnestler's 2018 C++ extraction (https://github.com/rnestler/pns-router, abandoned at KiCad's 2018 state).
- License: GPL-3.0-or-later. All 86 files under KiCad's `pcbnew/router` are GPL-3.0-or-later (checked at commit 302b2ba1014b2f116ab38d69ffa8c6d1c633ed85). A Rust port that follows the KiCad design closely is a derivative work, so AGPL is not an option without a clean room approach, and LibrePCB (GPLv3) would otherwise inherit AGPL's network clause for the combination.
- Scope of milestone 1: single net interactive routing with the three modes, via placement and layer switching, posture handling, optimizer. Dragging is milestone 2. Differential pairs, tuning, arcs later.
- Upstream context: Urban Bruhin (LibrePCB) asked in June 2025 for exactly this, a standalone library, preferably a Rust crate on crates.io, and offered to do the LibrePCB integration himself (https://librepcb.discourse.group/t/13/26, LibrePCB/LibrePCB#1537). In a 2026-09 chat he restated that the main blocker is somebody committing to set up and maintain the library, and that maintenance means regularly integrating KiCad's changes. KiCad's `pcbnew/router` received about 100 commits in the twelve months before 2026-09-07.
- Toolchain: the user installs rustup (stable plus 1.92.0 for MSRV checks) on the host and a distrobox from `librepcb/librepcb-dev:ubuntu-24.04-4` for building LibrePCB. The host (bazzite) had no cargo, cmake or Qt6 at project start.
- Process: from 2026-09-07 on, at most one LLM subagent runs at a time, work items are handled in series (user instruction).
- Reference clones live under `~/dev/ref/` (kicad sparse shallow, horizon shallow, pns-router shallow).

## Architecture decisions

Tags: #architecture #geometry #determinism #ffi

- Coordinates are i32 nanometres, exactly KiCad's envelope (about plus or minus 2.1 m). Products of coordinates are computed in i64 after computing differences in i64, and `rescale` uses i128 as KiCad does. Reason: every tolerance and epsilon in the KiCad router is calibrated for this numeric envelope, and bit compatible behaviour is the goal for the regression fixtures. LibrePCB's i64 nanometres are range checked at the host boundary.
- The shape hierarchy is an enum, not a trait hierarchy, so the collision dispatch matrix is a match the compiler checks for completeness.
- No arcs in the line chain for milestone 1. LibrePCB has no arc traces. The arc reference vector parallel to the point vector (doc/reference/kicad/01-geometry.md section 14.3) is the planned extension.
- Items live in an arena with generational ids. No raw pointers, no deferred free garbage pool, no pointer identity anywhere. A stale reference is a detectable error.
- The world is a two level overlay exactly like KiCad: every query visits the branch and the root only, never a parent chain. Branching a non root node copies the branch overlay (index of added items, override set, joints). The root keeps one large spatial index built at sync time, branches keep small ones.
- Determinism rules: no HashMap or HashSet is ever iterated, containers that are iterated are Vec, IndexMap or IndexSet. Obstacle ties are broken on (distance, item uid). Uids come from a per world counter. Algorithms take an explicit iteration budget, never the wall clock. Settings are explicit parameters, no global router instance.
- The shove loop returns effects that the caller applies, instead of mutating items in place while iterating (doc/reference/kicad/04-shove-and-optimizer.md section 8.3).
- The crate has no FFI. LibrePCB's `libs/librepcb/rust-core` will depend on the crate and expose `ffi_router_*` functions through cbindgen, the same pattern LibrePCB already uses for the `interactive-html-bom` crate by the same maintainer. The RuleResolver implementation for LibrePCB is Rust code in rust-core working on a plain data snapshot of the board.
- LibrePCB integration starts as a new board editor tool next to the existing draw trace tool. Whether it replaces the existing tool is a later decision for upstream.
- Edition 2024, MSRV 1.92 (LibrePCB's pinned Rust), rustfmt with 2 spaces and 80 columns like LibrePCB's rust-core.
- Dead or inert KiCad code is not ported. Each reference note lists what to skip, and each porting work item must consult that list.
