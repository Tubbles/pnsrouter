## The orphan net for routes started in free space

Tags: #decision #placer #rules #parity #kicad

- `RuleResolver` gains a required `orphaned_net() -> NetId`, the port of `ROUTER_IFACE::GetOrphanedNetHandle` (`pns_router.h:118`, `pns_kicad_iface.cpp:3020`), and `LinePlacer::start` places a route that starts on nothing on it (`pns_line_placer.cpp:1386`). It sits on the resolver because `AlgoContext { resolver, .. }` is what replaced `ROUTER::GetInstance()->GetInterface()`, and a second host trait for one method was not worth it.
- Contract: stable for the resolver's life, `net_code` of it zero or below, and distinct from every net a snapshot item carries. The third clause is the subtle one: KiCad's `OrphanedItem()` carries `NETINFO_LIST::UNCONNECTED`, which is 0 (`netinfo_list.cpp:315`), the same code as the board's net 0, but it is a separate `NETINFO_ITEM` and the collision ladder compares handles (`pns_item.cpp:188`), so a free space head keeps clearance from unconnected copper while being "same net" with its own fixed tail.
- `NetId` semantics are now stated precisely: `None` is a non conductive obstacle only (clearance always applies, never same net); netless copper carries a host id (KiCad hands its net 0 item through, `pns_kicad_iface.cpp:1691`, so two netless pads are same net there); free space routes carry the orphan.
- The three resolvers pick different ids: `FixedClearance` uses `NetId(0)` (its net numbering already starts at one), the KiCad harness and LibrePCB's `LibrePcbRules` use `NetId(u32::MAX)` with a `-1` special case in `net_code`, because their `net_code` would otherwise saturate it to `i32::MAX` and report a real net.
- Result: `simple-shove-1` replays at 28 added / 13 removed, KiCad's golden exactly, and is no longer ignored. Three of the four replayable goldens now match; `issue24132` waits on `.kicad_dru`.
- One existing test was passing on a broken route: `undoing_restores_the_direction_and_the_via_flag_of_the_stage` had its second leg collide with the first (null net) and asserted on an undefined direction. Its second leg now runs south, away from the north seed.
- LibrePCB gap recorded in `doc/librepcb-integration.md` section 1.6: the FFI maps net zero to `None`, so netless LibrePCB copper is a non conductive obstacle to the engine where KiCad's shares one net handle. Closing it needs the C++ side to intern a net for unassigned copper.

## LibrePCB step 4: the headless session wrapper, and the outline bug

Tags: #librepcb #ffi #decision #bug

- `BoardPnsRouter` (`libs/librepcb/core/project/board/boardpnsrouter.{h,cpp}`) lives in core next to `BoardPnsSnapshot`, not in the editor library the design note first named: no UI, no undo stack. Section 3.1 of `doc/librepcb-integration.md` is corrected and 3.1.1 lists the FFI as built.
- FFI shape decided: the session object keeps its latest `PreviewFrame`, `CommitDiff` and hover answer inside itself and C++ reads them through count and index accessors, one handle and one deleter. Hover answers host ids the same way. New `repr(C)` enums (`PnsPreviewStyle`, `PnsNewGeometryKind`, `PnsStartResult`, `PnsFixOutcome`) rather than bare integers, matching the snapshot half. Cursor points are clamped to the engine range rather than rejected, since a cursor has no board item to name. `ffi_pnsrouter_new` and `ffi_pnsrouter_set_settings` share one settings derivation.
- Step 2 bug found on the way: the board outline went over as one `Shape::Simple`, which is filled, so the whole board interior was an obstacle and no route could start on any pad of any fixture project. Fixed as KiCad syncs `Edge_Cuts` (`pns_kicad_iface.cpp:2047`): one zero width segment solid per edge, compound flagged, sharing one host id. Committed separately from step 4. Note 1.9 of the integration design had the wrong sentence and is corrected.
- Engine traps the wrapper documents rather than hides: `Router::undo_last_segment` straight after a fix answers `None` because the fix clears the head (`src/placer/line_placer.rs`, the `:1636` region), so a move has to come first as KiCad's host does; `Router::set_sizes` mid placement only applies from the next leg. `assign_host_ids` is not exposed yet and step 5 needs it so a session can recognise what an earlier commit placed.
- Verification detail: rust-core's `cargo clippy --lib` does not compile the `ffi` module (not a default feature); the check that matters is `cargo clippy --lib --features ffi -- -D warnings`. `--all-targets` fails on pre-existing test lints. `clang-format` is not in the container image; the new C++ was formatted by hand against `.clang-format`.

## LibrePCB step 5: the commit applier

Tags: #librepcb #decision #undo

- `CmdBoardApplyPnsCommit` (`libs/librepcb/editor/project/cmd/`) is one `UndoCommandGroup` per route that builds itself inside `performExecute` through `execNewChildCmd`, so every anchor lookup sees the writes of earlier children. Section 4 of the design note was rewritten to match; the `beginCmdGroup`/`appendToCmdGroup` recipe is gone.
- Two facts of the board model the note had missed: `BI_NetSegment` re-checks cohesion after every add and remove (`bi_netsegment.cpp:201`, `:282`), so `CmdBoardNetSegmentRemoveElements` cannot remove a middle net line on its own (removals go through `CmdRemoveBoardItems` and its splitter) and a router via cannot be added alone (it goes in with the first net line ending on it). A via no net line ends on gets a net segment of its own rather than being dropped.
- Merging: the near end of a net line chooses the net segment, so a far end in a foreign segment gets a stand in net point that `CmdCombineBoardNetSegments` dissolves into the foreign anchor. That satisfies "one anchor must be a net point" by construction. At most one merge per net line.
- Anchors are found by walking `Board::getDeviceInstances()` and `Board::getNetSegments()` with exact position, layer and net, because the scene query the draw trace tool uses needs an open editor; router endpoints are exact integers so the fuzzy match is not wanted anyway.
- A route without a net becomes a net segment without a net signal; the model allows it (`bi_netsegment.h:60`, `:149`). Plane invalidation is left to the item lifecycle (`bi_netline.cpp:189`, `bi_via.cpp:120`).
- Vias the router only shoved are moved in place with `CmdBoardViaEdit::setPosition` before any removal, so the uuid in the file format survives.
- Rough edges recorded in TODO.md: the const pointers in `BoardPnsHostRef` and `BoardPnsNewItem::net` force `const_cast` in the applier, and `BoardPnsNewItem` carries both kinds' fields.

## LibrePCB step 7: the preview renderer

Tags: #librepcb #decision #ui

- `BoardPnsPreviewItems` (`libs/librepcb/editor/project/board/boardpnspreview.{h,cpp}`) pools `PrimitivePathGraphicsItem` and `PrimitiveCircleGraphicsItem`, parks surplus items between frames, and replaces the whole frame on every `update`. Four headless gtests over a real `BoardGraphicsScene` (precedent: `cmddragselectedschematicitemstest.cpp`).
- Colours: a trace draws on its copper layer's graphics layer with no fill, as `BGI_NetLine` paints; Tail and SemiSolid are lightened with min alpha 150 (the `BGI_Via` value); Collision uses the air wire colour because `GraphicsLayerList::boardLayers()` registers neither the DRC marker nor the selection role and a primitive with a null layer hides itself. The rat line shares the air wire colour at cosmetic width. Z order is above `ZValue_AirWires`.
- Hidden host items (shoved originals) are set to opacity zero, not invisible: `BGI_*` visibility is derived from the layer, so `setVisible(true)` would resurrect a trace on a switched off layer. Restored on the next frame that does not list them, on `clear()` and in the destructor. `BoardPnsHostRef` has no equality, so the set is split by type.
- The renderer holds the scene through a `QPointer`: closing the tab while routing destroys the scene before the FSM leaves the tool.
- No clearance halo: the primitives take a layer, not a colour, and nothing lowers alpha. Recorded in TODO.md with the other renderer gaps (the fixed tail renders brighter than the head, via styles are indistinguishable, violation clearance and forced layer are unused).

## Reading `.kicad_dru` in the replay harness

Tags: #kicad #testing #decision

- `tests/support/kicad_dru.rs` reads the one custom design rules file in the corpus, and `KicadRules` now answers `has_user_defined_physical_constraint` and folds the two physical rungs of the clearance ladder in (`pcbnew/router/pns_kicad_iface.cpp:951`, `:960`). `issue24132-shove-same-net-via` reaches its golden four added and one removed; the other three replayable cases are unchanged (2/0, 11/5, 28/13). The `#[ignore]` on its tier 2 test is gone.
- Precedence is KiCad's, and it is not "the largest wins": `EvalRules` walks the rules of one constraint type in load order and every match overwrites the fields it carries (`pcbnew/drc/drc_engine.cpp:1048`, `:1860`), so the last match wins and a later rule that sets only `min` leaves an earlier `opt` standing. Conditions are evaluated for both orders (`pcbnew/drc/drc_rule_condition.cpp:111`), and a one sided query keeps the single order, which is why a rule naming `B` never fires on one.
- The condition subset is `A.Type`, `A.NetClass`, the same on `B`, `&&`, `||`, `!` and parentheses. Anything else drops the rule and raises `has_unsupported_design_rules` rather than being approximated, because a `(layer ...)` clause the reader ignored would silently widen the rule while a dropped one is visible in an ignore reason.
- Two deviations. A hole answers `Via` for `A.Type`, because `RuleResolver` hands no arena and the hole's parent pad or via cannot be followed (`pns_hole.h:74`); it is KiCad's own fallback for a parentless item (`pns_kicad_iface.cpp:516`) and every pad on the one board with design rules is surface mount. And `um` is not accepted as a length: KiCad's expression lexer takes only `mil`, `mm` and `in` (`pcbexpr_evaluator.cpp:829`, `libeval_compiler.cpp:430`), so `2um` fails to compile there too.
- `tests/fixtures/sessions/kicad_shove_same_net_via.txt` was regenerated. The commit diff gained the moved via, and the recorded `max-clearance` went from 0.6 mm to 2.1 mm because `worst_clearance` now folds in the rule the way `GetBiggestClearanceValue` does (`pcbnew/board_design_settings.cpp:1795`). The new answer is the better one: it is KiCad's.
