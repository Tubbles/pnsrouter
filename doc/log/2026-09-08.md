# 2026-09-08

## Toolchain: plain podman, no host Rust

Tags: #toolchain #process

- Nothing is installed on the host. All builds and tests run in a podman container built from `dev/Containerfile`, which derives from LibrePCB's CI image `librepcb/librepcb-dev:ubuntu-24.04-4` and adds clippy and rustfmt (the image installs Rust 1.92 with the minimal profile). `dev/in-container.sh` is the single entry point.
- Reason: the user does not work interactively on this machine, so editor integration and a newer stable toolchain on the host buy nothing, and a container that matches LibrePCB's CI keeps the MSRV honest. Distrobox was considered and rejected because its convenience (display, DBus and GPU passthrough for GUI programs) is only needed for manual GUI testing, which will happen on the user's laptop instead.
- Rust on the host stays possible later without changing anything in the repository, since the scripts only wrap cargo.

## Vec2: integer arithmetic choices

Tags: #geometry #architecture

- `Vec2 + Vec2` and `Vec2 - Vec2` stay in i32 and panic on overflow in debug builds. Note 01 section 14.1 suggested returning a widened type from subtraction; rejected because it makes every expression mixed width. `Vec2::widening_sub` returns a `Vec2L` for the places (Seg, Box2) that need a difference that cannot overflow, and every product, norm and determinant widens its operands to i64 first.
- No `Ord` on `Vec2`. KiCad has two contradictory orders on `VECTOR2I` (`operator<` by squared magnitude, `std::less` lexicographic), so callers that need an order say which one. The joint map will use the lexicographic one explicitly.
- Division exists only by `f64` and rounds each component half away from zero through `kiround`, as KiCad's `operator/` does. `v / 2` does not compile on purpose, so midpoints are visibly rounded rather than truncated.
- `isqrt` is `u64::isqrt`; a test compares it with a transcription of KiCad's loop over the whole signed range.

## Milestone 1 findings while porting the geometry

Tags: #geometry #kicad #erratum

- The reference note doc/reference/kicad/03-router-placer-walkaround.md section 6 describes the side test in `HullIntersection` the wrong way round. The code (`pns_utils.cpp:455`) keeps a corner hit when some neighbouring line point lies on the positive side of a hull edge, which for a clockwise hull is the inner side. The port and its tests follow the code. An erratum line was added to the note.
- The `cl++` and `cl += 2` compensations in `SegmentHull` are computed after the offsets that should use them, so they only reach the degenerate zero length path. Reproduced as is; the walkaround's termination depends on hulls and the collision predicates agreeing to the nanometre, so no "fix" is made without a matching fixture.
- KiCad's `BOX2::SquaredDistance( const Vec& )` has a real bug (`box2.h:785`, the else arm subtracts the box's own edges). Not reproduced, nothing in the router calls it.
- The `INTERSECTION` index aliasing became the `Hit::Segment | Hit::Corner` enum as planned; `HullIntersection`'s modulo compensation has no counterpart.
- Ports were checked against compiled transcriptions of the C++ in the container (g++ is in the image) over tens of thousands of random cases for Direction45, the circle pushout and rect versus circle collision cells, and the three hull builders. That technique is cheap and should be the default for every tolerance sensitive routine in the next milestones.
- Deferred from milestone 1: arcs everywhere (`SHAPE_ARC`, `ArcHull`, the arc branches of the line chain, the rounded corner modes), `VECTOR2D` (meanders only), `EDA_ANGLE` (dragger, solid orientation), `RotatePoint` from trigo.h (check callers when the item model needs it), the polygon union in `SOLID::Hull` (replaced by a convex hull of the primitive hulls per DESIGN.md), rounded rectangle polygonisation (the router never builds a rounded rect), `PointAlong` (multi dragger).

## Milestone 2: rule resolver and item collision

Tags: #architecture #rules #determinism

- `RuleResolver::constraint` (KiCad's `QueryConstraint`) is defaulted to "no rule". Its only callers in KiCad are the length tuning placer and the host tool; the line placer, walkaround, shove, optimizer and node never call it. A host that implements nothing there still routes.
- The via hole self collision heuristic (`pns_item.cpp:65`) is kept for now, against DESIGN.md sections 4.2 and 11. It is reachable between two distinct stored vias with no line involved, so removing it changes answers KiCad's are known for, and `Line` does not exist yet to show that `LineVia::Linked` covers every case. Decide when `Line` lands, with a fixture showing the two agree.
- The extra nanometre at `pns_item.cpp:249` measured: with the strict shape comparison, a gap of exactly `clearance` and of `clearance - 1` do not collide, `clearance - 2` does. Pinned by a test; the hull builders are calibrated against this.
- KiCad expands the obstacle side into its hole as well as the head side, contrary to its own comment. The port follows the code; the identity pruning keeps the extra pass from reporting anything new.

## Milestone 2: spatial index and joint map

Tags: #architecture #dependencies #determinism

- `rstar` 0.13 is the first and only runtime dependency, for the per layer R-trees of the index. Note 01 section 14.5 recommended it; a hand rolled tree with insert and remove would be several hundred lines with no test history. The insertion box is stored alongside the handle so removal never misses a mutated item (KiCad's tree can). Query order is tree traversal order and nothing may depend on it; the node sorts candidates by `(distance, uid)`.
- The index stores un inflated boxes and every query inflates by the node's `max_clearance`, exactly as KiCad. That makes `max_clearance` a soundness parameter for hosts.
- Joint identity: a joint is an arena id. On a merge the first overlapping joint absorbs the others and keeps its id, where KiCad erases all and inserts a new one; only absorbed ids go stale. The tombstone a branch plants for a deliberately removed joint is a present key with an empty list, never a `(-1, -1)` joint. A joint that loses its last link keeps its id with an undefined layer range, as in KiCad.
- `visit_box` stops on the first `false` from the visitor. KiCad's tree returns out of one leaf only and keeps visiting siblings, which is why its obstacle set can exceed `m_limitCount`; the node must be written against the honest contract.
- `SetDeferred` / `BuildSpatialIndex`, KiCad's bulk load for the initial sync, is not ported until a measurement shows it matters.

## Milestone 2: the branching node

Tags: #architecture #determinism

- `World` owns the item arena, the node arena, the uid counter and the two caches (clearance by canonical id pair plus epsilon flag, hull by id, clearance, thickness and layer, returned as `Rc<LineChain>`). The rule resolver is a query parameter, never stored.
- Item ownership is a `home` set per node instead of KiCad's owner pointer. There is no garbage pool: an item removed in the node it was added in leaves the arena immediately, together with its hole, and its id goes stale. A root item removed from a branch is shadowed in `overrides` (with its hole) and stays alive until the commit removes it from the root.
- `commit` reproduces KiCad exactly, including two things worth knowing: it kills every branch of the root, not only the committed one, and its addition dispatch ignores freestanding holes, so a mechanical hole added in a branch is lost on commit as in KiCad (the public `add` indexes one).
- Queries visit the branch index and then the root index filtered through the overrides, through one private helper; no read path walks the parent chain. Obstacle lists are deduplicated by item and sorted by `(item uid, head uid)`, hit tests and net lists by uid. The `(distance, uid)` order belongs to `NearestObstacle`.
- The collision search honours `limit_count` against an index whose early stop really stops, so obstacle lists never exceed the limit; KiCad's can.
- `KiCad::QueryJoints` filters root joints against a set of items and therefore never filters; reproduced as no filter. Edge exclusions are copied into branches, where KiCad's are not (a branch of KiCad's never sees them).
- `collide.rs` gained the accumulating form (`collide_into`), which keeps obstacles found through a hole even when a later test discards the item's own collision, exactly like KiCad's context set.
- Left for the shove work item: `FixupVirtualVias` and its two errata (a dead `n_seg >= 3` branch, a `locked_seg` leaking across joints).

## Milestone 2: the Line type and line assembly

Tags: #architecture #determinism

- `Line` is a value, never stored in a node. Its via is `LineVia::Owned(Item) | Linked(ItemId)`; a clone deep copies an owned via and re nets it to the copy's net, and aliases a linked one, which is KiCad's copy constructor made explicit.
- `links_valid_in` records the node the links were resolved against. It is provenance, not liveness: KiCad's `Add( LINE& )` lets two lines share a segment, and removing one leaves the other with a stale handle. Every consumer skips a link the arena no longer knows instead of trusting the count; a test pins it.
- `assemble_line` uses one `VecDeque` in place of KiCad's three 128 KiB stack arrays and has no vertex limit. A line gained a `source` host id, copied from the seed segment and back onto every segment it is stored as, so a host identity survives a reroute (KiCad does the same through `ITEM::m_sourceItem`).
- `Line::walkaround` around one hull was diffed against a C++ transcription over about 320000 random hull and line pairs, byte identical. Two KiCad code paths were found inert in the process: the second `ON_EDGE` neighbour tier (`pns_line.cpp:578`) can never fire, and the `OUTSIDE` visited fallback never fired in the sample. Both are transcribed and documented.
- The via self collision heuristic in `collide.rs` is still in place. `Line::via_item` hands the collision code a stored reference for a linked via (identity prunes it) and an unstored one for an owned via; the fixture that shows the heuristic is redundant belongs to the line collision task.
- Left for the dragger milestone: `DragCorner`, `DragSegment` and their helpers. `ClipToNearestObstacle` has no caller in this KiCad revision.

## Milestone 2 closed: line collisions and nearest obstacle

Tags: #architecture #determinism #rules

- The via self collision heuristic (`pns_item.cpp:65`) is retired. With `LineVia::Linked` the stored via's identity prunes both the via pass and the hole pass; an owned via built by the placer owns no hole until `World::add_via` stores it, so the hole to hole branch is never entered and the copper pair is same net exempt, KiCad's answer. KiCad needs the heuristic only because `VIA::Clone` drills a fresh hole. The one changed answer: two distinct stored vias at one position with equal padstack, net and drill now collide hole to hole; that is two real objects, not a self collision, and the revert is one commit if a shove fixture ever disagrees.
- `nearest_obstacle` scans candidates in item uid order, so a distance tie goes to the smaller uid, the zero distance break is a pure optimisation, and the no intersection fallback picks the smallest uid instead of the lowest address. The result carries `found_intersection` so a caller can tell the fallback from a line that starts on a hull; KiCad cannot.
- Line versus line collisions are not supported: only the head side may be a line, since lines are never stored. The shove, optimizer and multi dragger call sites that collide two lines will decompose one side into segments.
- Not ported: the thread pool and the sequential hull copy that feeds it, and the bounding box hull simplification for the 90 degree corner modes (`pns_node.cpp:330`), which needs the routing settings and lands with the walkaround.
- Milestone 2 exit test lives in `tests/world.rs` and exercises the public API only.

## Milestone 3: settings and walkaround

Tags: #architecture #determinism #erratum

- `RoutingSettings` and `Sizes` are plain `Copy` data passed as parameters through an `AlgoContext { resolver, settings, debug }`, the replacement for `ALGO_BASE`'s inherited fields and for `ROUTER::GetInstance()`. Host only settings (snap to tracks and pads) and dead ones (suggest finish, walkaround time limit) are not in the struct. `shove_time_limit_ms` is carried as data and read by nothing, per the no wall clock rule.
- The 90 degree box hull is closed. KiCad never closes it and `LINE::Walkaround` tests `PointInside`, which is false on an open chain, so KiCad's 90 degree walkaround has no hull interior; an erratum was added to note 03 section 5. This is the one deliberate routing difference so far.
- The per cluster wall clock bail out of `processCluster` is dropped; termination rests on the finite cluster and the 1000 step cap of `Line::walkaround`.
- The classification loop over disabled policy slots is reproduced (a disabled slot comes back almost done over an untouched copy of the input); `singleStep`'s discarded constant return is not.
- The shortest policy's back off against processed items goes through `check_colliding_line` with a `restricted_set` filter (the port of `COLLISION_SEARCH_OPTIONS::m_filter` narrowed to its one use), because a line is never the obstacle side here.
- `World::assemble_cluster` (KiCad's `TOPOLOGY::AssembleCluster`) lives on the world for now; DESIGN.md section 9 still wants a `topology.rs` when more of TOPOLOGY is ported.
- A minimal `DebugDecorator` trait with no op defaults exists in `src/debug.rs`; the event log and the full decorator are milestone 5.

## Milestone 3: posture solver and optimizer core

Tags: #architecture #determinism

- `MouseTrailTracer` is a straight port; its only singleton use (the debug decorator) became `AlgoContext::debug`. `GetPosture` takes only the cursor point in this revision. The solver always reasons in 45 degree corners because KiCad's `BuildInitialTrace` calls there leave the corner mode at its default.
- The optimizer core (`merge_obtuse`, `merge_step`, `merge_full`, `merge_colinear`, the area, preserve vertex and keep topology constraints, `corner_cost`) is ported; the dead collision cache, the no op corner count and vertex range constraints, the undefined 45 degree angle constraint, the unused cost estimator methods and the diff pair passes are not. `SMART_PADS` and `FANOUT_CLEANUP` are accepted and skipped until the pad passes land.
- Quirks reproduced and documented: `merge_full` answers by segment count, so it can report "unchanged" over a line it rewrote and "changed" when only `simplify2` fired (the shove drops the result on false); `merge_step` checks constraints over one more vertex than it splices, leaving a duplicate for `simplify2`; the area constraint's `strict` flag is carried and never read, as in KiCad; the preserve vertex constraint keeps the anchor on the line, not as a corner.
- Deviations: constraints are cleared per `optimize` call instead of accumulating (pure predicates, same answers); an explicit pass budget guards the two coarse to fine loops although both are finite; a span whose lines do not intersect is skipped in `merge_obtuse` where KiCad dereferences an empty optional.
